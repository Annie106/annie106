适用 v 0.4.x.x

这是一个部署、修改和使用此博客的操作指南。

本指南将带你从零开始，了解如何修改、使用并部署这个博客。

GitHub项目地址：https://github.com/annie106/annie106

开始之前：你需要知道四个词的含义

后面会一直出现这四个词，先混个脸熟。

  • GitHub：放代码的网站。可以理解成程序员的网盘，顺便还能免费帮你把网站挂到网上。
  • 仓库：GitHub 上的一个项目文件夹。你的博客就是一个仓库。
  • VS Code：微软出的免费编辑器，我们用改博客里的文字和颜色，可以当成高级记事本。
  • GitHub Pages：GitHub 附赠的免费托管服务。打开它，你的博客就有公开网址了。

操作十分简单，无需服务器和域名

第一步：注册 GitHub

打开 github.com，点右上角 Sign up注册。已经有账号就跳过。

只有用户名需要多想一下：它会出现在你以后的博客网址里，所以用英文加数字，别用中文和空格。

用户名想清楚再填

假设你填 xiaoming，以后博客网址就是 https://xiaoming.github.io/仓库名。注册完基本改不了。

第二步：下载源码

A 下载 ZIP（最简单）

打开 github.com/annie106/annie106，点右上角绿色的 Code 按钮，菜单最下面有一项 Download ZIP，点它。

下载完找到压缩包，右键解压（Windows 11 可以直接选「全部解压缩」）。

先解压，再改

别在压缩包的预览窗口里直接改文件，改动存不进去，网页也会打不开。一定要先解压出来。

B Fork 一份（打算做成自己的网站就选这个）

在项目页面右上角点 Fork，再点 Create fork。GitHub 会把整个项目复制到你的账号下，之后你改的是自己那份。

好处是仓库已经在你自己名下了，第八步开 Pages、传文件都不用再折腾。

选哪个

只想先看看长什么样：选 A。
打算直接做成自己的网站：选 B。

第三步：装 VS Code

去 code.visualstudio.com 下载，双击安装包一路点下一步。安装时如果看到「添加到右键菜单」之类的选项，建议勾上，以后右键文件夹就能直接打开。

装完打开 VS Code，按 Ctrl + Shift + X 打开扩展面板，搜 Chinese 装上中文语言包，重启一下界面就变中文了。

再搜 Live Server（作者 Ritwick Dey）装上。这个插件能让你改一下、浏览器立刻自动刷新，强烈建议装。

然后点左上角「文件」→「打开文件夹」，选中你解压出来的博客文件夹。

打开的是文件夹，不是单个文件

要打开整个博客文件夹，这样左边会列出所有文件。如果只打开了 index.html，左边是空的，改起来会迷路。

第四步：在电脑上预览

用 VS Code 打开博客文件夹后，在左边点一下 index.html，然后点 VS Code 右下角状态栏上的 Go Live。浏览器会自动打开，之后你每次保存文件它都会自动刷新。

找不到 Go Live 的话，就在左边文件列表里右键 index.html，选「Open with Live Server」。

别用双击 index.html 的方式预览

直接双击打开的话，地址栏是 file:///C:/... 这种形式，浏览器会限制一部分功能：背景音乐点了没反应、文章里的内嵌页面显示空白、点微信图标复制不了。所以测试时请用 Live Server。

根目录

index.html 是整个博客的骨架。首页、文章列表、文章详情、电影、关于，五个界面全挤在这一个文件里。你的头像、名字、导航栏、社交图标、页脚也都在这里改。

movie.html 是独立的视频播放页，想加视频改它底部的 VIDEO_LIST。

favicon.svg 是浏览器标签页上那个小图标。share_cover.jpg 是把链接分享到微信、QQ 时显示的封面缩略图，改法见「6.9 换分享卡片封面」。README.md 是纯文字说明，不显示在网页上。

images 文件夹

站内用到的图片统一放这里，比如 images/manor_photos/manor_01.jpg。图片和页面分开放，改版、换页面时图片不用跟着搬。

引用时写相对路径：根目录的页面直接写 images/manor_photos/manor_01.jpg；project_subpage/blog/ 下的页面要往上退两级，写成 ../../images/manor_photos/manor_01.jpg。路径区分大小写，GitHub Pages 上 Images/ 和 images/ 是两个不同的文件夹。

css 文件夹

只有 style.css 一个文件，但它是整个博客的化妆师。颜色、字号、行高、圆角、深色模式的配色全在这里，想换色调只改这一个文件就够。

js 文件夹

script.js 是博客的大脑，也是第二重要的文件。你写的所有文章都在这里面，标签筛选、页面切换也归它管。

theme.js 管深浅色切换，还会记住访客的选择。touch-hover.js 修的是「手机上点一下按钮，按钮就一直亮着不恢复」的问题，它给页面加一个标记，样式表据此决定要不要显示鼠标悬停效果。image-loading.js 管图片加载：先用模糊占位顶上，图加载完再淡入变清晰，也负责 data-fast-src / data-slow-src 那套高速/慢速链接的切换。background-music.js 管背景音乐，歌单在文件最开头。copyToClipboard.js 就是「点一下微信图标自动复制」那个功能。

archive/ 文件夹里是留档的旧文件，页面不会加载它们。music-player.js 是旧版播放器（现在用 background-music.js），feedback-tx.html 是旧版腾讯问卷反馈页（现在用 blog/feedback.html）。不用管它们，删了也不影响网页。

关于 project_subpage

project_subpage/ 下面分成两个文件夹：blog/ 是博客自带的页面（没做完的项目、未开放文章提示页、反馈表单、反馈成功页、这份指南），projects/ 是放你自己项目页的地方。想加新页面，在 projects/ 里建一个文件夹放 index.html 就行。

这些页面可以配置成「把子页面嵌进来显示」或「点一下跳过去」，写法在 6.6 节。移动或改名之后，记得同步改 js/script.js 里写死的路径，否则会 404。

第六步：把它改成你自己的样子

动手之前先备份

把 index.html 和 js/script.js 各复制一份，名字后面加个「备份」。改坏了随时能拿回来。

通用技巧：用搜索找位置

下面经常说「搜索某个词」。做法是在 VS Code 里按 Ctrl + F，把那个词粘进去按回车，光标就跳过去了。

6.1 换头像

打开 index.html，搜索 class="avatar"：

<img
    class="avatar"
    src="图片地址"
    alt="头像"
    loading="lazy"
/>

改 src 引号里的东西就行。填网络图片的网址（要 https:// 开头），或者把图片放进博客文件夹再填相对路径，比如 images/avatar.jpg。第二种更稳，网络图片哪天挂了就显示不出来。

图片建议用正方形，边长 200 到 500 像素就够，太大只会让网页变慢。

6.2 换网站图标

所有 HTML 页面都引用根目录的 favicon.svg。根目录页面搜索 rel="icon"，引用路径是：

<link rel="icon" type="image/svg+xml" href="favicon.svg">

子目录页面也要加同样的标签，但 href 要按页面所在目录写相对路径。例如 project_subpage/blog/ 下的页面用 ../../favicon.svg，project_subpage/projects/download/ 下的页面用 ../../../favicon.svg。新建或移动 HTML 页面时检查一下路径，避免图标 404。

想换图标时，直接替换根目录的 favicon.svg，所有引用它的页面都会一起更新。

6.3 改顶部导航栏

搜索 nav-links：

<ul class="nav-links" id="navLinks">
    <li><a href="#" class="active" data-nav="home">首页</a></li>
    <li><a href="#" data-nav="blog">文章</a></li>
    <li><a href="movie.html" data-nav="movie">电影</a></li>
    <li><a href="about-rh-studio.html" data-nav="about">关于</a></li>
</ul>

每行结构都是 <li><a ...>显示的文字</a></li>。改文字就改中间那几个字；想删一项整行删掉；想加一项复制一整行粘在下面再改。

别碰 data-nav

data-nav="home" 这种东西是给程序认的，删了或改了，点导航就没反应。你只改标签中间的文字。

顺带说一句「关于」这一项：它指向的 about-rh-studio.html 其实不存在，但不影响使用——点它的时候程序会直接切到 index.html 内置的关于界面。想改关于页内容，搜索 view-about。

6.4 改右侧那排图标

就是微信、QQ、邮箱、深浅色那一排。搜索 class="social-links"：

<div class="social-links">
    <a href="javascript:void(0);" onclick="copyToClipboard('你的微信号', '微信号已复制')" title="微信">
        <i class="ri-wechat-fill"></i>
    </a>

    <a href="javascript:void(0);" onclick="copyToClipboard('你的QQ号', 'QQ号已复制')" title="QQ">
        <i class="ri-qq-fill"></i>
    </a>

    <a href="javascript:void(0);" onclick="copyToClipboard('你的邮箱', '邮箱已复制')" title="邮箱">
        <i class="ri-mail-line"></i>
    </a>

    <a href="#" title="RSS 订阅"><i class="ri-rss-line"></i></a>

    <button class="theme-toggle" id="themeToggle" aria-label="切换深色模式" title="切换主题">
        <i class="ri-moon-line"></i>
    </button>
</div>

换成自己的联系方式，就改 copyToClipboard() 括号里第一个东西，两边都要留英文单引号。第二个是点击后的提示文字，随便写。

想换图标：<i class="ri-wechat-fill"></i> 里的 ri-wechat-fill 就是图标名，去 remixicon.com 挑一个替换掉。

想加一个，就复制一整段 <a ...>...</a> 粘在下面。比如加抖音：

<a href="https://www.douyin.com/user/你的主页" target="_blank" rel="noopener noreferrer" title="抖音">
    <i class="ri-tiktok-fill"></i>
</a>

不想要哪个就整行删掉。

最后那个按钮别删

结尾那个 theme-toggle 是深浅色切换开关，删了网页不会坏，但访客就没法切深色模式了。它身上的 id="themeToggle" 也不能删。

6.5 改首页文字

都在 index.html 里，搜索 hero-section 找到这一整块。常见几处：

  • 大名字：搜 hero-name
  • 一句话简介：搜 hero-bio
  • 详细描述：搜 hero-description
  • 所在地、职业、起始年份：搜 hero-meta，一行一个 <span>
  • 左上角站点名和副标题：搜 site-title

「所在地」那几项里，前面 <i class="ri-map-pin-line"></i> 是图标，后面才是文字。改文字就行。

6.6 写文章、改文章

文章都在 js/script.js 开头。打开它，搜索 const blogPosts，里面每一项就是一篇文章：

{
    id: 1,
    title: '文章标题',
    date: '2026-05-03',
    excerpt: '这里写摘要，会显示在文章卡片上',
    tags: ['随笔'],
    pinned: false,
    featured: true,
    content: `
        <p>正文第一段</p>
        <h2>一个小标题</h2>
        <p>正文第二段</p>
    `,
},

各字段的意思：

  • id：文章编号，不能跟别的文章重复
  • title / date / excerpt：标题、日期、摘要。日期就是个文字，不会自动排序
  • tags：标签，用来看筛选按钮，可以有多个，写成 ['随笔', '阅读']
  • pinned：写 true 就是置顶
  • featured：true 显示在首页，false 只在文章页显示
  • isPublic：可选。设为 false 后，文章详情区域会显示“当前文章不对外开放”，并隐藏文章标题、元信息和正文；改为 true 或删掉此字段即可重新开放。没有设置时默认开放
  • content：正文，写在反引号（键盘左上角 ` 那个键）中间，可以用 <p> 分段、<h2> 加小标题
  • embeddedPage：填相对路径如 'project_subpage/projects/xxx/index.html'，这篇文章会把那个网页嵌进来显示
  • externalPage：填路径，点文章直接跳过去。跟上面那个二选一

文章正文和通过博客打开的同源内嵌页面里的图片，都会自动使用模糊占位和加载完成后的清晰化动画。普通图片写 <img src="..." alt="..." width="..." height="..." loading="lazy"> 即可；建议填写图片实际宽高，减少加载时的页面跳动。需要高速链接时，同时写 data-fast-src（高速）和 data-slow-src（慢速/大图预览），系统会自动按 20 秒规则选择、后台预加载慢速图，并在高速失败时回退。想要贴合图片的占位效果，可再加 data-tone="#8c806b" 和小尺寸图片的 data-lqip="data:image/jpeg;base64,..."。

加新文章就复制一整段（从 { 到 },），粘到数组里改掉内容和 id。

暂停展示不等于保密

isPublic: false 会在文章详情区域显示未开放提示，并且不把正文插入前端页面 DOM。可是这是静态博客，文章数据仍在公开的 js/script.js 文件中，访客仍可能查看源码。因此这个开关只是控制页面展示，不能用来保护敏感或机密内容。

新手最容易栽在这三个地方
  • id 重复：两篇用同一个 id，会导致点击错乱，其中一篇打不开
  • 逗号漏了：每篇结尾那个 }, 的逗号不能少
  • 引号写成中文的：必须是英文单引号 '，不能是 ‘ 或 ’

保存后如果网页突然一片空白，八成就是上面某一条。按 Ctrl + Z 撤销再检查。

首页顶上那排筛选按钮，搜索 'all', '置顶' 能找到，改成你自己常用的标签。'all' 是「全部」，建议留着。

文章卡片右上角那个「⋯」菜单可以给某篇文章单独配，搜索 const articleMenus：

const articleMenus = {
    10: [
        { label: '返回文章列表', type: 'link', url: 'index.html#blog' },
    ],
};

前面的 10 是文章 id。没配过的文章会自动显示「复制文章链接」「查看评论」「问题反馈」三个默认项。

菜单项支持三种类型：link（打开指定网址或页面）、article（打开站内文章详情）、externalPage（打开这篇文章自己配置的独立页面）。想加一项就照上面的格式复制一行。

反馈表单在 project_subpage/blog/feedback.html，反馈类型包括「文章问题」「Bug 反馈」「功能建议」「排版样式」和「其他」。

6.7 把文章分享给别人

每篇文章都有一个专属链接，形式是 你的网址/?article=文章id。别人打开这个链接，会直接进入对应文章详情。把 isPublic 设为 false 的文章会显示未开放提示，而不会显示正文。

拿到链接有两种办法：

  • 文章里点「分享」：打开文章后，标题上方有一个「分享」按钮。手机点它会唤起系统分享面板（微信、QQ 等），电脑点它会直接把链接复制到剪贴板，然后右上角弹出提示。
  • 卡片菜单里复制：在文章卡片的「⋯」菜单里点「复制文章链接」，效果一样，不用先进文章。
链接里的数字就是文章 id

?article=10 里的 10 就是文章数据里的 id。所以改 id 会让已经发出去的链接失效——想改文章内容就改标题和正文，别动 id。

如果链接里的 id 不存在（文章被删了），页面会自动回到首页并清掉地址栏里的参数；如果文章设为未开放，则会在文章详情区域显示未开放提示。

本地双击打开时分享会受限

用 file:// 直接双击 index.html 时，浏览器的剪贴板权限被禁用，点「分享」会弹出一个输入框让你手动复制。用 http 服务器预览、或者部署到网上之后就正常了。

在微信里点「分享」会先复制链接，再弹引导

微信内置浏览器既没有系统分享面板，也不允许网页主动弹出「分享给朋友」。所以微信里点「分享」时，会先自动复制链接，再弹出一个提示浮层，告诉用户点右上角的「···」→「分享给朋友」。链接已经复制好了，也可以直接粘贴给好友。

鸿蒙 NEXT 版微信用的是 ArkWeb 内核，同样按微信内处理，不需要额外配置。判断逻辑在 js/script.js 的 isWeChatBrowser()。

它怎么区分微信和手机浏览器：先看 UA 里有没有 MicroMessenger / wxwork，或者页面里有没有微信注入的 WeixinJSBridge——命中一个就确定是微信。没有这些标记、又是 ArkWeb 内核时，还要排除 HuaweiBrowser、UCBrowser、Quark、MQQBrowser 这些普通浏览器（脚本里叫 NON_WECHAT_APP_BROWSER），否则华为/鸿蒙手机自带浏览器也会被当成微信，点分享就会弹出一个指向右上角、但其实不存在的「···」引导。手机浏览器里点分享，正常走系统分享面板；面板不可用则复制链接加一句提示。

6.8 用内嵌页面做图文文章

普通文章的正文写在 content 里，够用，但排版一复杂就别扭了。想做带大图、能点开放大的图文页，用 embeddedPage：把正文写成独立的 HTML 文件，再让文章把它嵌进来。

本站的《归宿里的两帧》就是这么做的，可以直接照抄：

  • 页面文件：project_subpage/blog/manor_photo.html
  • 图片：根目录 images/manor_photos/（manor_01.jpg / manor_02.jpg）
  • 文章数据：js/script.js 里 id 为 11 的那一项，embeddedPage: 'project_subpage/blog/manor_photo.html'

换照片只改两处 <img>。因为页面在 project_subpage/blog/、图片在根目录的 images/，所以要往上退两级：

<img src="../../images/manor_photos/manor_01.jpg"
     alt="第五人格归宿花房，两个角色站在绣球花与白色玩偶之间"
     width="1728" height="1079">

路径规则：页面在哪个文件夹，往上数几层才到根目录，就写几个 ../。project_subpage/blog/ 是两层，所以是 ../../images/...；project_subpage/projects/download/ 是三层，就是 ../../../images/...。图片名和文件夹名区分大小写，线上 Images/ 和 images/ 是两个不同的东西。

照片点开是当前页放大，不跳新标签页

点一下照片在当前页放大，再点一下图片（或按 Esc、点背景、点右上角 ×）退出。

这里有个坑：文章内嵌页面的高度等于整篇文章的高度，position: fixed 的「视口」就是这一整块 iframe，预览层会被拉成一张超高的遮罩、还盖不住顶部导航。所以脚本会把预览层连同 #manorLightboxStyles 整块搬到外层页面，用外层视口定位。改这段时别删掉 id="manorLightboxStyles"，否则内嵌后预览层没有样式。

别把网盘短链直接写进 src

网盘、图床的分享链接通常是跳转短链，点开会被 302 到带签名的临时地址（十几分钟就过期）。写进 src 的话，文章放一会儿图就全裂了。正确做法是先把图下载到 images/ 里，再用本地相对路径引用，由 GitHub Pages 直接提供。

图片建议长边 1600px 左右、JPEG 质量 85、单张不超过 500KB。原图动辄 1MB，手机上加载会明显变慢。

6.9 换分享卡片封面

把链接发到微信、QQ 时，聊天窗口里会显示一张缩略图。这张图由页面 <head> 里的 og:image 指定，图片文件是根目录的 share_cover.jpg。

换图的完整步骤：

  1. 把新图放进根目录（建议正方形、至少 300×300，文件名可以沿用 share_cover.jpg）；
  2. 打开 index.html，在 <head> 里找到这三处，把地址里的文件名改成新文件名：
<meta property="og:image" content="https://你的域名/share_cover.jpg">
<meta name="twitter:image" content="https://你的域名/share_cover.jpg">
<link rel="image_src" href="https://你的域名/share_cover.jpg">

同时把 og:image:width 和 og:image:height 改成新图的真实尺寸。

两个必须避开的坑

① 必须写绝对地址。 content="share_cover.jpg" 这种相对路径微信抓不到，卡片会显示灰色占位图标。要写完整的 https://你的域名/share_cover.jpg。

② 不要用外部图床或 CDN 的头像地址。 如果那个图床开了 Referer 鉴权（防盗链），微信抓取时不带本站 Referer，会直接拿到 403，同样显示灰图标。鉴权本身也不能关，否则流量会被盗刷。正确做法是把图片放进仓库，由 GitHub Pages 直接提供。

改完没生效？是缓存

微信会长期缓存抓取结果，同一个链接可能一直显示旧图、甚至一直是灰图标。测试时务必换一个从没分享过的链接（比如在网址后面加 ?v=2），否则很容易误判成"改了没用"。

另外，本站所有文章共用 index.html?article=N 一个页面、靠 JavaScript 换内容，而微信不会执行 JavaScript 后再抓图，所以全站共用同一张封面。标题会随文章变，图片不会。想让每篇文章有不同封面，需要为每篇文章单独生成静态 HTML 页。

6.13 改「关于」页面

「关于」不是单独的网页文件，它是 index.html 里内置的一个界面。点导航栏的「关于」时，程序直接切过去显示，所以改它也是在 index.html 里改。

如果想让别人直接打开「关于」页面，可以把博客首页链接后加上 ?view=about，例如 https://你的网址/?view=about。打开这个链接会直接显示关于页面，不需要在关于页面增加分享按钮；离开关于页后这个参数会自动清除。

打开 index.html，搜索 view-about，能找到这一整块。从上到下依次是这几处：

  • 小标签、大标题、一句话标语：搜 about-eyebrow、about-title、about-tagline
  • 标题下面那段介绍：搜 about-lead
  • 「关于我们」的正文段落：搜 about-copy
  • 右边的信息列表：搜 about-facts
  • 最下面的内容方向标签：搜 about-topics

标题和标语都是普通文字，直接改标签中间的字：

<p class="about-eyebrow">RH STUDIO · ABOUT</p>
<h1 class="about-title">RH 工作室<span>.</span></h1>
<p class="about-tagline">一间安静写字的小小工作室 · 用博客记录生活的回响</p>

标题里那个 <span>.</span> 是跟着的小圆点，不想要就把这半截删掉。

「关于我们」的正文，一段一个 <p>。想加一段就复制一整行粘在下面再改字：

<section class="about-copy">
    <h2>关于我们</h2>
    <p>第一段正文</p>
    <p>第二段正文</p>
</section>

右边的信息列表，一项就是一个 <div>，前面 <dt> 是名目，后面 <dd> 是内容：

<dl class="about-facts">
    <div><dt>创始人 / 负责人</dt><dd>Annie</dd></div>
    <div><dt>工作室性质</dt><dd>个人工作室 · 独立博客</dd></div>
    <div><dt>联络邮箱</dt><dd><a href="mailto:你的邮箱">你的邮箱</a></dd></div>
</dl>

邮箱那一项里，href="mailto:..." 后面要换成真实邮箱，这样访客点一下就能直接发信。想删一项，就把对应的整个 <div> 删掉。

最下面的内容方向是一串 <span>，想加一个词就复制一个 <span>新词</span> 粘进去：

<div class="about-topic-list">
    <span>生活随笔</span><span>读书札记</span><span>旅行碎片</span>
</div>
导航里那个 about-rh-studio.html 不用管

导航栏「关于」的 href 写的是 about-rh-studio.html，这个文件其实不存在，但不影响使用——点击时程序会拦下跳转，直接切到内置的关于界面。所以不用去新建这个文件，也别改 data-nav="about"。

别在 script.js 里改关于页

js/script.js 的 siteConfig 里有一个 aboutText 字段，看着像是关于页的正文，但程序并没有读取它，在那里改不会有任何变化。详见 6.14 节。

6.14 有个地方改了没用

在 js/script.js 里搜索 siteConfig，会看到一段配置：

const siteConfig = {
    authorName: '...',
    subtitle: '...',
    bio: '...',
    location: '...',
    occupation: '...',
    blogStartYear: '...',
    email: '...',

改这里不会有任何变化

这段配置目前的代码并没有真正读取它，只是留在文件里备用。你在里面改名字、改简介，网页上不会有反应。

要改个人信息，请去 index.html 里改（看 6.5 节）。这个坑很多人踩过，改了半天没动静就是因为改错了地方。

6.15 换整体配色

打开 css/style.css，最上面就是颜色定义，搜索 :root：

:root {
    --color-bg: #ffffff;              /* 页面背景 */
    --color-surface: #fafafa;         /* 卡片背景 */
    --color-border: #eaeaea;          /* 边框 */
    --color-text-primary: #1a1a1a;    /* 主要文字 */
    --color-text-secondary: #6b6b6b;  /* 次要文字 */

这是浅色模式的颜色，改这些色值就能换主题色。色值是 # 加六位数字或字母，可以搜个「在线取色器」选好颜色复制过来。

6.16 调文章页顶部那行「返回 / 分享」

打开文章后，标题上面有一行：左边「‹ 返回」，右边「分享」。它们的上下留白在 css/style.css 里，搜索 .article-topbar：

.article-topbar {
    display: flex;
    align-items: center;
    justify-content: space-between;
    gap: 12px;
    flex-wrap: wrap;
    padding-top: 4px;      /* 这一行和导航栏之间的额外空隙 */
    margin-bottom: 28px;   /* 这一行和文章大标题之间的空隙 */
}

为什么要多这么两行？因为页面顶部有一层固定不动的「渐变虚化」遮罩（手机上 110px 高、电脑上 150px 高），它会把刚进入文章页时贴着顶部的内容一起糊掉。把这一行往下推一点，按钮就不会落在虚化的最浓处。

想让按钮再往下，两个数要一起改

现在「导航底边 → 按钮」和「按钮 → 标题」都是 28px（导航自带 24px 下边距 + 这里的 4px，以及下面的 28px），所以这一行是上下居中的。

如果只把 padding-top 调大、margin-bottom 不动，这一行就会「上面空、下面挤」，看着偏上。想整体下移就两边一起加：比如都改成 8px / 32px，上下仍然是 32px 对 32px。

另外注意：虚化层是固定高度的，按钮下移到一定程度后就不会再被糊到，再往下推只是浪费空间。

6.17 搜索结果里显示几个标签

搜索结果每一条下面会列出这篇文章的标签，和文章详情页完全一致——文章有几个标签就显示几个，不截断。之前这里只取前两个，所以「第五人格 / 随笔 / 社交」这种三标签的文章在搜索里会少一个，看着像标签对不上。

这段逻辑在 js/script.js 里，搜索 const tagChips：

const tagChips = (post.tags || []).map(tag => {
    const isHit = keywords.some(keyword => tag.toLowerCase().includes(keyword));
    return `<span class="search-result-tag${isHit ? ' is-hit' : ''}">${escapeHtml(tag)}</span>`;
}).join('');
  • post.tags 就是文章数据里的 tags 数组，想全部显示就别加 .slice()。
  • 如果你确实只想显示前几个，把 .map( 前面改成 .slice(0, 2).map( 即可。
  • 命中了搜索关键词的标签会自动带上 is-hit 类，显示成黄色；样式在 css/style.css 里搜 .search-result-tag.is-hit。

标签多了会不会挤坏？不会。.search-result-tags 是 flex-wrap: wrap，放不下会自动换行。

6.18 手机端搜索面板的弹出动画

手机上点搜索，面板是从屏幕底部整块滑上来的，不是原地淡入。相关样式在 css/style.css 里搜 手机端进场 / 退场动画：

/* 进场：从屏幕下方 100% 处滑到位，0.38 秒，先快后慢 */
.search-panel {
    transform: translateY(100%);
    transition: transform 0.38s cubic-bezier(0.32, 0.72, 0, 1);
}
.search-overlay.is-open .search-panel {
    transform: translateY(0);
}

/* 退场：0.26 秒，加速曲线，收得更干脆 */
.search-overlay:not(.is-open) .search-panel {
    transition: transform 0.26s cubic-bezier(0.4, 0, 1, 1);
}

面板内部还有一层「逐层入场」：标题行、搜索框、内容区、落款依次延迟 0.04s / 0.08s / 0.12s / 0.16s 出现，像内容跟着面板一起落下来。这些延迟只写在 .search-overlay.is-open 状态里，所以关闭时内容会立刻跟着面板走，不会被拖在后面。

想更快 / 更慢

改 0.38s（进场）和 0.26s（退场）就行，但 JS 里的等待时间要一起改：

  • openSearch() 里手机端等 300ms 才聚焦输入框——太早的话键盘会在滑动途中把可视区改矮，面板高度会跳一下；
  • closeSearch() 里手机端等 300ms 才把面板 display: none——比退场的 260ms 长一点，动画才不会被掐断（掐断的表现是「啪」地消失，而不是滑走）。

两个数字都在 js/script.js 里，搜索 searchMobile.matches ? 300 就能找到。

如果访客的系统开了「减弱动态效果」，上面这些位移和延迟会自动全部关掉，面板直接出现、内容也强制可见，不会因为初始透明而白屏。这段写在 @media (prefers-reduced-motion: reduce) 里。

6.19 卡片右上角「⋯」按钮的底色

文章卡片右上角那个三点按钮，原本是完全透明的，鼠标移上去才有一点灰。现在改成常驻一层浅灰圆底，看着更像一个能点的按钮。搜索 .options：

.options {
    background: #f1f1f1;       /* 平时：浅灰圆底 */
}
html:not(.is-touch-input) .options:hover {
    background: #e6e6e6;       /* 鼠标悬停：深一档 */
}
.options:active,
.post-card.menu-open .options {
    background: #dedede;       /* 按下、或菜单已展开 */
}

深色模式在下面一点，搜索 [data-theme="dark"] .options，用的是 rgba(255, 255, 255, 0.08) 这种浅色微光。两边要分别改，否则深色模式下按钮会变成一块突兀的浅灰。

想让按钮更淡就调小透明度（例如 0.03），想更明显就调大。

6.20 手机上搜索入口的灰底

「最新文章」「全部文章」标题右边的搜索按钮，在电脑上是透明的、鼠标移上去才变灰；手机上没有悬停这回事，所以它在手机上改成常驻浅灰底 + 一圈极淡描边，一眼就能看出可以点。

这段写在 css/style.css 的 @media (max-width: 600px) 里，搜索 .search-trigger：

.search-trigger {
    height: 26px;
    padding: 0 9px 0 6px;
    border-radius: 999px;
    border-color: rgba(17, 17, 17, 0.06);   /* 描边 */
    background: rgba(17, 17, 17, 0.05);     /* 常驻灰底 */
    color: var(--color-text-secondary);
}

深色模式要单独写一段（搜索 [data-theme="dark"] .search-trigger），换成 rgba(255, 255, 255, 0.08)——浅灰底落在深色页面上等于没有。

只影响手机

这些规则都包在 max-width: 600px 里，电脑上还是原来的透明样式 + 悬停变灰，Ctrl K 键帽也照常显示。

屏幕特别窄（≤330px）或标签太多时，按钮会自动缩成一个只有放大镜的圆形，灰底会跟着变成圆形，不会破版。

第七步：改字号和字体

所有字号都在 css/style.css 里，单位是 rem，1rem 差不多等于 16px。

文章正文字号

搜索 .article-content：

.article-content {
    font-family: var(--font-serif);
    font-size: 1.05rem;      /* 改这个数字 */
    line-height: 1.78;       /* 行高，越大行距越松 */
}

觉得字小就把 1.05rem 改成 1.15rem；觉得行挤就把 1.78 改成 1.9。

文章大标题搜 .article-full-title，首页大名字搜 .hero-name，里面都有 font-size: 2rem;，改小一点就写 1.6rem。

想整体调大，有个省事的办法

在 css/style.css 的 :root 里加一行：

:root {
    font-size: 17px;        /* 默认是 16px */
}

因为全站字号都是用 rem 算的（相对根字号），改这一个数，所有文字会按比例一起变大。

调完记得看手机效果

字调太大会让手机上排版错位。改完按 F12 打开开发者工具，点左上角那个手机图标切到手机视图看一眼。

换字体

字体也在 css/style.css 最上面：

:root {
    --font-sans: 'PingFang SC', 'Noto Sans SC', 'Microsoft YaHei UI', 'Microsoft YaHei', sans-serif;
    --font-serif: 'Noto Serif SC', 'Songti SC', 'STSong', 'SimSun', serif;
}

--font-sans 管导航、标题这类界面文字，--font-serif 管文章正文。浏览器会从左往右找第一个你电脑上装了的字体，所以想换字体就把名字放到最前面。

第八步：传到 GitHub，变成真正的网站

改满意了，就可以让别人也能访问了。这一步分两件事：先把文件传上去，再开启 Pages。

A 网页上传（最简单）

登录 GitHub，点右上角的 +，选 New repository。仓库名用英文，比如 myblog——这个名字也会出现在你的网址里。下面选 Public（公开），因为私有仓库用不了免费的 Pages。其他初始化选项都不要勾，直接点 Create repository。

创建好之后，页面上有个 uploading an existing file 的链接，点进去。然后把你博客文件夹里的所有文件和文件夹一起拖进上传区域。

注意是拖文件夹里面的东西，不要把最外面那层文件夹本身拖进去。等它传完，下面随便写一句说明，点绿色的 Commit changes。

网页上传的毛病

传不了空文件夹，而且以后每改一次都得重新传一遍。打算长期写博客的话，建议用下面那种。

B GitHub Desktop（推荐）

GitHub 官方的桌面软件，图形界面，不用敲命令。去 desktop.github.com 下载装上，用你的账号登录。

点 File → Add local repository，选中你的博客文件夹。如果它提示这不是一个 Git 仓库，就点它给的那个 create a repository 链接确认创建。

回到主界面，左下角有个 Summary 框，随便写句说明，比如「改了头像」。然后点 Commit to main，再点右上角的 Publish repository。弹窗里记得把 Keep this code private 的勾去掉（必须公开），确认仓库名，发布。

以后每次改完文件，就重复「写说明 → Commit → 点 Push origin」这三下。

C 命令行

在博客文件夹里打开终端，一行一行执行：

git init
git add .
git commit -m "第一次提交"
git branch -M main
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main

以后更新只要三行：

git add .
git commit -m "更新说明"
git push

开启 Pages，拿到网址

文件传上去了但还不能访问。最后一步：进你的仓库页面，点上面的 Settings，左边菜单里找到 Pages。把 Source 从 None 改成 Deploy from a branch，Branch 选 main，右边文件夹保持 / (root)，点 Save。

等一两分钟刷新这个页面，顶上会冒出一个绿色提示，里面就是你的网址：

https://你的用户名.github.io/仓库名/

比如用户名 xiaoming、仓库名 myblog，网址就是 https://xiaoming.github.io/myblog/。如果仓库名刚好跟用户名一样，网址会短一点。

以后更新内容：本地改好 → 传上去 → 等一两分钟 → 刷新网站，改动就生效了。

打开是 404？

先检查首页文件名是不是 index.html，大小写必须完全一致，Index.html 不行。再检查文件是不是传到了仓库根目录，而不是套在子文件夹里。刚开 Pages 那几分钟打不开是正常的。还有，网址结尾那个斜杠别漏。

第九步：哪些东西不能删

删错文件是把博客搞坏的最快方式，动手前看一眼。

删了网页就会坏的

文件 删掉会怎样
index.html 整个网站打不开，直接 404。这是首页，必须有。
css/style.css 网页变成裸奔状态：没有颜色、没有排版，文字全挤成一团。内容还在但完全没法看。
js/script.js 文章全部消失（数据就在这个文件里），导航点了没反应，页面也切不动。这个最不能删。
js/theme.js 深浅色按钮失灵，点了没反应。
js/touch-hover.js 网页不会坏，但手机上点深色模式按钮、播放按钮之后，按钮会一直保持按下的样式不恢复。
js/copyToClipboard.js 点微信、QQ、邮箱图标没反应。不报错，就是没效果。
js/image-loading.js 网页不会坏，但文章图片会直接硬加载：没有模糊占位，加载时页面会跳一下，高速/慢速链接的自动切换也失效。

删了也没事的

archive/music-player.js 是旧版播放器，页面根本没加载它。README.md 是纯文字说明，不参与网页显示。

看你用不用得上的

js/background-music.js：不想要背景音乐就删掉，记得顺手把 index.html 最下面加载它的那行 <script> 一起删掉。

movie.html：不用电影功能就删掉，同时把导航栏里对应的那行 <li> 也删掉，不然点进去是空白。

project_subpage/ 里的页面也属于可选项。删了之后文章卡片「⋯」菜单里的「评论」「反馈」点进去会 404，页脚里指向它们的链接也会失效。不想用就把引用它们的链接一起改掉。

代码里也有几处不能乱动

  • 导航栏上的 id="navLinks" —— 删了手机端菜单按钮会失效
  • 导航项里的 data-nav="home" 之类 —— 删了导航点了没反应
  • 深色模式按钮的 id="themeToggle" —— 删了切换开关失效
  • index.html 最下面那几行 <script src="js/..."></script> —— 这是加载功能脚本的，删一行少一个功能
  • 文章里的 id —— 不能重复，也最好别改，改了菜单配置会对不上

几个常见问题

改完文件，网页没变化？
九成是浏览器缓存，按 Ctrl + F5 强制刷新。还不行就看看文件是不是真保存了——VS Code 里文件名旁边有小圆点就表示没保存。

网页突然一片空白？
一般是 js/script.js 被改坏了：漏逗号、引号不配对、或 id 重复。按 Ctrl + Z 撤销再检查。也可以按 F12 打开开发者工具切到 Console，红色报错会告诉你第几行有问题。

图片不显示？
检查路径拼写（大小写敏感，Images/a.jpg 和 images/a.jpg 是两个东西）、图片是否真在那个文件夹、网络图片的网址能否直接打开。

部署完样式全乱了？
多半是 css/style.css 没传上去，或者传的时候目录结构变了。去仓库里核对路径跟本地是否一致。

能用记事本改吗？
能，但另存为时编码必须选 UTF-8，不然中文会变乱码。

一页纸清单

  1. 注册 GitHub，想好用户名
  2. 下载源码：Download ZIP 解压，或者 Fork 一份
  3. 装 VS Code + 中文包 + Live Server
  4. 用 VS Code 打开博客文件夹，点 Go Live 确认能打开
  5. 备份 index.html 和 js/script.js
  6. 在 index.html 里改头像、名字、导航、社交图标、页脚
  7. 在 js/script.js 里写文章（id 别重复）
  8. 在 css/style.css 里调配色和字号
  9. 传到 GitHub，Settings → Pages 开启，拿到网址
  10. 把网址发给朋友
保持创造

博客是一个持续成长的过程。不要停止学习和创造。
