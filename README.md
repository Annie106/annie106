# Annie 的个人博客

> 纯 AI 构建

一个使用原生 HTML、CSS 和 JavaScript 编写的静态个人博客，无需安装依赖或执行构建。

## 功能

- 首页、文章列表、文章详情、电影和关于页面
- 根据文章标签筛选，支持置顶文章
- 全站搜索（首页与「全部文章」标题右侧的搜索按钮，或 <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>K</kbd>、<kbd>/</kbd> 打开）：
  - **检索范围**：标题、摘要、标签、正文。正文会先剥掉 HTML 标签再建索引，所以能搜到只出现在正文里的词；`isPublic: false` 的文章不会出现在结果里（搜得到却点不进去，比搜不到更让人困惑）。
  - **排序**：字段权重 × 命中质量（标题 > 标签 > 摘要 > 正文），标题开头命中额外加权；多个关键词按「与」匹配、允许分别落在不同字段（如「阅读 工作流」）；分数相同时置顶优先、再按 id 新的在前。
  - **结果呈现**：列表行而不是网格卡片，扫描效率更高；标题与命中片段里的关键词高亮，片段会截取命中点前后的正文，并标注命中原因（标题 / 摘要 / 标签 / 正文）。结果里的标签**与文章详情页完全一致**（全部展示、不截断），命中关键词的标签会高亮成黄色，所以「第五人格 / 随笔 / 社交」这类三标签文章在搜索里也是三个，不会少一个。
  - **空状态**（自上而下）：**最近搜索**（有历史才显示，本地保存最多 6 条，可清空）→ **按标签**（三列网格，6 个高频标签，带每项文章数）→ **最近更新**（最新 4 篇，可直接点开）→ **快速前往**（首页 / 全部文章 / 电影 / 关于）→ 三条搜索小贴士。这套顺序让手机上打开面板就能一屏看全，键盘上方不再是一大片空白。没有结果时给出「只搜某个词」的退一步入口。
  - **交互**：输入 180ms 防抖（中文输入法合成期间不检索），检索时显示骨架屏 + 转圈并有最短展示时间；<kbd>↑</kbd><kbd>↓</kbd> 选择、<kbd>Enter</kbd> 打开、<kbd>Esc</kbd> 先清空再关闭；打开时锁背景滚动并把焦点移入面板（Tab 在面板内循环），关闭后焦点还给入口按钮。
  - **返回上一页（两级）**：搜索面板打开时，返回键 / 侧滑 / 后退按钮的行为分两级——
    1. 输入框里**有关键词** → 只清空关键词，回到空白搜索页（最近搜索 / 按标签 / 最近更新 / 快速前往），面板不关，光标留在输入框；
    2. 输入框**已经空了** → 收起面板，回到原页面。

    和 <kbd>Esc</kbd>、面板左上角的「‹」按钮完全一致。打开搜索时会往浏览器历史压一条记录，所以这一下不会把用户带出站点；关闭面板会把那条记录退掉，历史里不留空记录。
  - **从文章返回时回到「打开搜索前」的那一页**：点搜索结果打开文章后，按返回（文章页「返回」按钮或系统返回键）会收起搜索面板、回到打开搜索之前的页面（首页还是首页、文章列表还是文章列表），不会重新弹出搜索面板，也不会残留关键词和结果。实现上靠 `openArticle` 里的一次 `replaceState`：把「搜索中」那条历史记录换成返回快照，再 `pushState` 文章记录，所以历史链是干净的。
  - **移动端键盘避让**：手机上是全屏面板，高度取自 `visualViewport.height` 而不是 `100vh`，并用 `visualViewport.offsetTop` 补偿 iOS 的可视区上移——键盘弹起时面板整体缩短，输入框和结果始终留在键盘上方。输入框字号固定 16px，避免 iOS 聚焦时把整页放大。
  - **移动端弹出动画**：手机上面板不是「原地淡入」，而是整块从屏幕底部滑上来——进场 `translateY(100%) → 0`，0.38s，曲线 `cubic-bezier(.32,.72,0,1)`（先快后慢，收尾不弹跳）；退场 0.26s，换成加速曲线 `cubic-bezier(.4,0,1,1)`，手指一松就迅速让位。面板内部再逐层入场：标题行 → 搜索框 → 内容区 → 落款，依次延迟 40 / 80 / 120 / 160ms 淡入并上浮 10px，看起来像内容跟着面板一起落下来；退场时这些延迟不存在，内容随面板一起走。遮罩仍然只做淡入淡出，面板本身不再叠淡入，避免两层透明度叠在一起发灰。JS 侧的等待时间也与之对齐：手机端打开后 300ms 才聚焦输入框（否则键盘会在滑动途中改矮可视区，面板高度跳一下），收起后 300ms 才 `display:none`（退场 260ms，提前隐藏会把动画掐断）。`prefers-reduced-motion: reduce` 下全部退化为瞬间出现，且内部各层强制 `opacity: 1`，不会因为初始透明态导致内容消失。
  - **移动端搜索入口**：放大镜后面带一个很小的「搜索」二字（0.66rem）。触屏没有悬停，所以这个入口在手机上是**常驻浅灰底 + 极淡描边**的胶囊（深色模式下换成 `rgba(255,255,255,.08)` 的浅色微光），一眼就能看出可以点，而不是像一段飘着的标题文字；按下时底色再深一档。这一行放不下时会自动收起、只剩图标——由 JS 实测「标题 + 搜索按钮 + 标签行」的自然宽度并与可用宽度比较，标签变多或屏幕太窄都会触发，不依赖写死屏宽；330px 以下另有 CSS 兜底。首页标题行强制不折行（标题 + 搜索在左、标签在右），标签行拿走剩余宽度并在手机上横向滚动，标签再多也不会把布局挤成两行。

    「全部文章」页的标签是从所有文章收集来的，可能多到一行放不下，所以它**允许换行**：手机上第一行是「全部文章 + 搜索 + 首页」，标签在下面铺成多行。

    桌面端有两种形态，由 JS 实测切换（`is-tag-wrap` 类）：放得下时标签紧跟标题、整体靠右；放不下时标签独占第二行、从左边开始并与「全部文章」对齐——避免换行后那一坨标签孤零零缩在右边。这样既不会切掉标签，也不会出现横向滚动条。首页的行为不受影响。

    「全部文章」标题旁还有一个「首页」按钮，和「搜索」同款胶囊（同高度、同字号、同一水平线），点一下回到首页顶部。
  - 逻辑见 `js/script.js` 的「全站搜索：检索核心 / 交互」「搜索入口：空间自适应」，样式见 `css/style.css` 的「全站搜索」段落。
- 直链下载页（`project_subpage/projects/download/index.html`）的搜索：按名称、版本、简介、功能检索，多关键词按「与」匹配，命中处高亮，带结果计数、清空按钮、Esc 清空和空状态出口；输入 140ms 防抖，手机上搜索框与按钮保持同一行。
- 文章卡片二级菜单支持三种类型：打开站内文章、跳转到文章配置的独立页面（`externalPage`）、或自定义链接（`link`）
- 文章详情支持内嵌独立 HTML 页面（`embeddedPage`），自动调整高度并适配主题
- 文章分享：打开文章时地址栏带上 `?article=<id>`，文章页顶部的「分享」按钮和卡片菜单均可复制该链接；别人打开链接直达对应文章，链接失效时自动回到首页
- 微信内分享：微信内置浏览器（UA 含 `MicroMessenger` / `wxwork`，或注入了 `WeixinJSBridge`）不支持 Web Share API，也没有让网页主动唤起「分享给朋友」面板的接口，因此点击分享按钮会先复制链接、再弹出指向右上角「···」的引导浮层；鸿蒙 NEXT 版微信（ArkWeb 内核，UA 可能不带 `MicroMessenger`）同样按微信内处理。**注意**：鸿蒙/华为手机自带的浏览器也是 ArkWeb 内核，所以判断时会先排除 `HuaweiBrowser`、`UCBrowser`、`Quark`、`MQQBrowser` 等已知普通浏览器标记（见 `js/script.js` 的 `NON_WECHAT_APP_BROWSER`），否则手机上的普通浏览器也会被误判成微信、弹出无意义的引导浮层；其它浏览器仍走系统分享面板/复制链接。桌面版微信（Windows/macOS）的分享入口在左上角，浮层的箭头与文案会自动换成「左上角」
- 单篇文章可通过 `isPublic: false` 暂停正文访问，点击文章或打开其直达链接会在文章区域嵌入 `project_subpage/blog/article_unavailable.html` 提示页；将其改为 `true` 即可重新开放
- 关于页面可通过 `?view=about` 直达，无需添加分享按钮
- 所有 HTML 页面使用根目录的 `favicon.svg` 作为浏览器图标
- 分享卡片封面：根目录 `share_cover.jpg`（1080×1080），通过 `index.html` 里的 `og:image` / `twitter:image` / `link rel="image_src"` 暴露给微信等平台抓取。**必须是绝对地址**，相对路径抓不到。**不要填 CDN 头像地址**——如果 CDN 开了 Referer 鉴权（实测不带 Referer 返回 403，只有带本站 Referer 才 200），而微信抓取时不带本站 Referer，填了只会显示灰图标；鉴权也不能关，否则流量会被盗刷。所以封面必须放在仓库里由 GitHub Pages 提供。换图后微信有缓存，旧链接可能仍显示旧图
- 反馈表单支持文章问题、Bug 反馈、功能建议、排版样式和其他类型
- 新增博客使用指南文章，提供完整的项目配置、修改和部署教程
- 页面状态记忆：离开文章、切换标签页或关闭页面后返回时，自动恢复之前的视图、滚动位置和筛选状态
- 适配移动端的导航和页面布局
- 点击图标复制微信号、QQ 号和邮箱地址（优先使用 Clipboard API，兼容旧浏览器）
- 首页背景音乐卡片，提供播放/暂停、音量、进度和收起控制；用户的音乐启用状态保存在浏览器本地
- 独立视频播放页 `movie.html`：视频列表配置在 `VIDEO_LIST` 数组，支持侧边播放列表面板、加载动画、左上角水印，以及针对验证码、地区限制、解码失败、资源禁用等情况的详细错误提示与"重新加载 / 换一个视频"操作
- 子页面：博客自带页面在 `project_subpage/blog/`（没做完的项目、未开放文章提示页、反馈表单、反馈成功页、使用指南），自己的项目页在 `project_subpage/projects/`
- 关于页在 `index.html` 的 `view-about` 视图内展示（RH 工作室介绍），由 `data-nav="about"` 触发切换

## 修改内容

- **个人资料和页面文字**：编辑 `index.html`，包括姓名、简介、所在地、职业、头像、社交联系方式及关于页面内容。首页"最新文章"标签筛选默认为 `置顶 / 社交 / 阅读 / 随笔 / 第五人格`，可在 `js/script.js` 的 `renderTagPills` 中调整。
- **文章**：编辑 `js/script.js` 中的 `blogPosts` 数组。文章可设置标题、日期、摘要、标签和 HTML 正文；将 `pinned` 设为 `true` 可置顶。设 `isPublic: false` 时，文章详情会嵌入 `project_subpage/blog/article_unavailable.html`；如需修改未开放提示的内容和样式，直接编辑该文件即可。文章标题、元信息和正文会隐藏；改为 `true` 或删除该字段即可恢复开放。此开关只控制页面显示，不是安全措施：静态站点的文章正文仍可从公开的 `js/script.js` 源码中读取。`embeddedPage` 可将独立 HTML 页面嵌入博客文章详情（自动调整高度并适配深色模式）；`externalPage` 可配置跳转到独立页面。卡片二级菜单统一配置在 `articleMenus` 中，以文章 `id` 为键；未单独配置的文章默认显示“复制文章链接”“查看评论”和“问题反馈”三个选项。菜单项支持：
  - `article`：打开站内文章详情
  - `externalPage`：打开该文章数据中的 `externalPage` 链接
  - `link`：打开指定的 URL 或 HTML 页面
- **归宿照图文页**：`project_subpage/blog/manor_photo.html`（文章 id 11，通过 `embeddedPage` 内嵌）。照片放在根目录的 `images/manor_photos/`（`manor_01.jpg` / `manor_02.jpg`），页面里写相对路径 `../../images/manor_photos/xxx.jpg`。换照片只需改这个文件里两个 `<img>` 的 `src`，并把新图放进 `images/manor_photos/`（建议长边 1600px 左右、JPEG 质量 85、单张不超过 500KB）。`alt` 顺手改掉。字体与字号跟博客正文一致（`--font-sans` / 1.05rem / 1.78）。页面用 `is-embedded` 标记判断是否处于 iframe 中：内嵌时自动隐藏页内大标题（避免和文章标题重复）、内容列左对齐到文章标题，独立打开时显示完整刊头。

  - 点击照片在当前页放大，**再点一下图片**（或按 `Esc`、点背景、点右上角 ×）退出，不会跳新标签页。内嵌时 iframe 高度等于整篇文章高度，`position: fixed` 的「视口」是整块 iframe，会把预览层拉成超高的遮罩还盖不住顶部导航，所以脚本会把预览层连同 `#manorLightboxStyles` 整块搬到父文档，用父页面视口定位。改这段时注意别删掉 `id="manorLightboxStyles"`，否则内嵌后预览层没有样式。

- **分享文章**：每篇文章的链接形式为 `index.html?article=<id>`。打开文章时地址栏会自动带上该参数，返回列表时自动清除；开放文章页顶部有「分享」按钮（微信内先复制链接并弹出引导浮层，其它移动端唤起系统分享面板，桌面端复制链接），卡片「⋯」菜单里也有「复制文章链接」。未开放文章的直达链接会在文章区域显示提示。链接中的 `id` 不存在时会清掉参数并回到首页。**改动文章 `id` 会使已分享的链接失效。**

  > **为什么微信里不能一键分享？** 微信内置浏览器不实现 Web Share API，也没有任何公开接口能让网页主动弹出「分享给朋友」面板。官方微信 JS-SDK 只能**配置**分享卡片的标题、摘要和缩略图，真正发起分享仍需用户手动点右上角「···」；且 JS-SDK 要求认证公众号、HTTPS 域名以及后端签名服务（用 `appId` + `secret` 换 `jsapi_ticket`），纯静态的 GitHub Pages 站点无法满足。所以本站采用「复制链接 + 引导浮层」的方案。
- **关于页面链接**：在博客首页链接后加上 `?view=about`，例如 `https://你的网址/?view=about`，即可直接打开内置关于页。
- **分享卡片封面**：微信/QQ/微博等把链接转发出去时，会抓取页面的 `og:image` 作为缩略图。相关标签在 `index.html` 的 `<head>` 里，三处地址必须保持一致：

  | 标签 | 作用 |
  | --- | --- |
  | `<meta property="og:image">` | 微信、QQ、Facebook 等主流平台 |
  | `<meta name="twitter:image">` | Twitter / X |
  | `<link rel="image_src">` | 部分旧版微信 / QQ 抓取器的兜底 |

  换封面图时要做三件事：

  1. 把新图放进仓库根目录（例如替换 `share_cover.jpg`）；
  2. 把上面三处地址里的文件名改成新文件名，**同时改 `og:image:width` / `og:image:height`** 为新图真实尺寸；
  3. 用**从没分享过的链接**测试（例如加 `?v=2`），因为微信会强缓存抓取结果。

  > **两个坑，务必避开：**
  >
  > 1. **必须用绝对地址。** `content="share_cover.jpg"` 这种相对路径微信抓不到，会退回灰色占位图标。要写成 `https://你的域名/share_cover.jpg`。
  > 2. **不要填第三方 CDN 的头像地址。** 本项目头像托管在开了 **Referer 鉴权**的 CDN 上，实测不带 Referer 返回 403、只有带本站 Referer 才 200；而微信抓取时不带本站 Referer，所以填 CDN 地址只会显示灰图标。鉴权也不能关——关了流量会被盗刷。**正确做法是把图放进仓库，由 GitHub Pages 直接提供。**
  >
  > 另外，微信抓取的是"被分享的那个 URL"。本站所有文章共用 `index.html?article=N` 一个页面、靠 JS 换内容，而微信不会执行 JS 后再抓，所以**全站共用同一张封面**，标题可以随文章变（`updateShareMeta()` 会改 `og:title`），但图片不会。想让每篇文章有独立封面，需要为每篇文章生成单独的静态 HTML 页。
- **网站图标**：根目录的 `favicon.svg` 是所有 HTML 页面的浏览器图标。子目录页面通过相对路径引用它；新建或移动页面时，记得检查 `<link rel="icon">` 的路径。
- **背景音乐**：编辑 `js/background-music.js` 中的 `musicList` 数组；每项包含歌曲标题、艺术家和音频地址。当前配置为单曲循环。
- **电影列表**：编辑 `movie.html` 中的 `VIDEO_LIST` 数组，为视频填写名称和播放链接。
- **样式**：编辑 `css/style.css`。几个常改的段落：
  - `.article-topbar`：文章页顶部「返回 / 分享」那一行的上下留白。它下面的 `padding-top` 和 `margin-bottom` 是一对——两边一起改才能让这一行在导航和标题之间保持居中；只改一边会看起来偏上或偏下。之所以要往下推一点，是因为顶部那层 `body::before` 渐变虚化（手机 110px / 桌面 150px）会把贴着顶部的内容糊掉。
  - `.search-trigger` 的 `@media (max-width: 600px)` 段：手机端搜索入口的常驻浅灰底与描边（深色模式另有一段 `[data-theme="dark"] .search-trigger`）。桌面端仍是透明 + 悬停变灰。
  - `.search-panel` 的 `@media (max-width: 600px)` 段：手机端面板的整块上滑进场（0.38s）/ 退场（0.26s）与面板内部逐层入场。改时长时记得同步 `js/script.js` 里 `openSearch` / `closeSearch` 的 300ms 等待，否则键盘会中途弹出、或退场动画被 `display: none` 掐断。
  - `.options`：文章卡片右上角「⋯」按钮的常驻浅灰圆底（深色模式在 `[data-theme="dark"] .options`）。
- **子页面**：博客自带页面在 `project_subpage/blog/`，项目页在 `project_subpage/projects/`，均为独立页面，可直接修改各自 HTML 内容。移动或重命名这些页面后，记得同步 `js/script.js` 里的 `embeddedPage` 和 `articleMenus` 路径。
- **归档文件**：`archive/` 里的文件不参与网页显示，仅作留存。`music-player.js` 是旧版播放器（已由 `background-music.js` 取代），`feedback-tx.html` 是腾讯问卷版反馈页（已改用 `blog/feedback.html`）。
- **页面状态记忆**：通过 `script.js` 自动实现。离开文章、切换标签页或关闭浏览器时，当前视图、标签筛选、滚动位置等状态会被自动保存；返回时自动恢复，无需额外配置。

## 本地运行

在项目根目录启动静态文件服务器：

```bash
python -m http.server 8000
```

然后访问 <http://localhost:8000>。也可以直接在浏览器中打开 `index.html`。浏览器可能会限制页面自动播放音乐，需要用户交互后才能开始播放。

## 部署

本项目是静态网站，可部署到 GitHub Pages 或其他静态托管服务。无需后端服务或构建步骤。
